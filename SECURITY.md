# Security scope

Trusted owned source/interpreter and ordinary owned local files assumed. Product
never executes packages, queries registries or networks, installs or edits lockfiles.
Keep client/employer/private data out of portfolio fixtures.

Exact native identities precede hooks. Whole-input admission blocks unknown
fields, cycles, malformed data and count/component violations, including inactive
candidates. Aliases count per occurrence. UTF8/lexical depth/numeric gates precede
JSON decode. Bounded Cartesian enumeration checks conditional requirements and
root-induced closure; false finite completeness is a principal risk. Incomplete
states discard modeled rows, even after witnesses. Compatible cycles are allowed.

Output fully encoded/capped before delivery, files exclusively created, counts/
flush/close checked. Failure can leave partial files. No hostile-filesystem,
links/reparse/race containment, atomicity/durability or hard RSS/time promise.
Native concurrent mutation excluded. A filesystem sandbox is not malware isolation.

Closed-catalog completeness is an input assertion. No-solution applies only to
that supplied finite universe. Real package existence/availability/compatibility/
security/unsupplied possibilities remain unknown. Retain minimal synthetic defect
inputs and expected behavior locally. Public messages/disclosure require separate
authorization; no external disclosure is automated.
